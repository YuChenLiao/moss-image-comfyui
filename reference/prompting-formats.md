# 三种提示词格式：Tag / Caption / Layout

前两个 reference 只讲 Tag 与混合写法。但 MOSS 还支持**结构化 Layout**——用 JSON 框位控制海报排版、漫画分格、多人占位。这一篇补上格式分流与 Layout 规范。

## 先选格式

| 需求 | 用哪个 | 理由 |
|---|---|---|
| 普通人物、场景、多人互动、复杂姿势 | **Caption / 混合**（L1–L3） | 位置大致即可，tag + 中文最稳 |
| 多处独立文字、指定区域排版、漫画分格 | **Layout** | 需要坐标约束，自然语言说不清 |
| 只是存成 JSON 文件方便管理 | Caption 外面包一层 JSON | 那是文件包装，不是 Layout |

判断线只有一条：**是否需要"某个东西必须落在指定区域"**。只是"左边一个人、右边一扇窗"，自然语言够了；"左三分之一站人、中间留白放标题、右下角三行小字"，才上 Layout。

细节多、想要电影感、手指要准、单人动作复杂——这些都不构成上 Layout 的理由，bbox 不是姿态骨架。

## 画风首句

不管哪种格式，**画风单独成一句，放在最前面**。

```
日式二维动漫插画，彩色线稿与层次化赛璐璐上色。[角色、服装、动作、场景、光线…]
```

它只描述整体视觉表现，不代替后面的环境光、材质和空间描述。只改画风时**只替换这一句**，后面的身份、服装、动作、构图、光源全部不动——不要借着换画风顺手换装或改场景。

Layout 里这句是 `summary.caption` 的第一句，不在每个 item 里重复。

## 质量词的取舍（与 SKILL.md 的差异）

SKILL.md 的 tag 模板带了 `masterpiece, best quality`，那是 Danbooru tag 体系的一部分。换成 Caption 或 Layout 时，**这两组不要带**——自然语言里堆 "best quality, masterpiece" 是空洞形容词，占位不产生可见结果。

| 格式 | 质量词 | 画师 |
|---|---|---|
| Tag / 混合（L1–L3） | 保留 `masterpiece, best quality` | `@画师名` |
| Caption 纯自然语言 | 不写 | 用户点名才写 |
| Layout | 不写，`meta` 里也不许塞 | 用户点名才写 |

## 多人：一个主语绑定一套属性

这是最容易翻车的地方。以下写法会让颜色、衣服、动作在两人之间漂移：

```
two women, red hair, black hair, blue jacket, yellow coat, holding a box
```

改成每人一句、属性归属明确：

```
站台上恰好两名女性。左侧短红发女性穿蓝夹克与黑长裤，递出一个绿色小盒子；
右侧高挑黑长发女性穿黄大衣与白长裤，伸手接向同一个盒子。两人都看着中间的盒子。
```

三条硬规则：**精确人数**（"只有两人、没有路人" ≠ "两个主角、背景人群不突出"）；**交接物只有一件**（别写成每人各拿一个）；**动作要说明谁对谁做**。

## 两个"左/右"

- **画面左/右**：观众看图的方向，用于站位和 bbox
- **角色自身的左/右**：人物解剖侧，转身后与画面方向相反

优先写看得见的关系："靠近镜头的手握住杯柄，远侧手托杯底"。确实需要自身某只手时写清楚（"她的右手"），再结合身体朝向核对。别同时给出互相矛盾的两侧暗示。

## Layout：JSON 规范

### 两步走：草稿 → 成稿

先在**左上角原点**的像素坐标系里画草稿，再机械转换成模型要的中心坐标。

**草稿**（自己看，不交出去）：

```json
{"width":1024,"height":1536,"bbox_coord_space":"abs","bbox_format":"xyxy",
 "summary":{"caption":"..."},"items":[{"label":"character","caption":"...","bbox":[x0,y0,x1,y1]}]}
```

约束：`0 ≤ x0 < x1 ≤ W`、`0 ≤ y0 < y1 ≤ H`，必须是真实像素，**不用百分比或 0–1 归一化**。

**成稿**（真正提交给 MOSS）：

根字段只有四个——`summary`、`items`、`bbox_coord_space="abs_centralized"`、`bbox_format="yxyx"`，**不含 width/height**，整段压成一行紧凑 JSON。

转换公式：

```
[x0, y0, x1, y1]  →  [y0 - H/2, x0 - W/2, y1 - H/2, x1 - W/2]
```

1024×1024 画布下，`[100,320,440,760]` → `[-192,-412,248,-72]`。原点与数组顺序同时变，负数是正常的。1536×1024 时宽减 768、高减 512，**两轴减的不是同一个数**。

带小数边时：左/上向下取整，右/上向上取整，再减中心。

### 字段

| 字段 | 要求 |
|---|---|
| `summary.caption` | 必填。画风首句 + 全局场景、人数、阅读顺序、共享光照 |
| `summary.meta` | 可选字符串数组，只放媒介/题材，**不许塞质量词或自动画师** |
| `summary.palette` | 可选，全局配色 |
| `summary.canvas` | 可选：`single` / `multi_panel` / `collage` |
| `items` | 非空扁平数组，所有对象同一层 |
| `item.label` | 只能是 `character` / `object` / `text` |
| `item.caption` | 必填，写外观、动作、关系、材质 |
| `item.bbox` | 必填四坐标 |
| `item.text` | `text` 项必填，存真正印出来的字 |
| `item.tags` / `item.palette` | 可选，补特征，不替代 caption |

**不增加** `style`、`id`、`children`、`parent`、`panels`、`panel_id`、`negative_prompt` 这些字段。

### 文字项

真排版的字用 `label="text"`，`text` 存原文，`caption` 描述颜色、字号层级、字体倾向、载体。只写"这里是标题"模型会自己编文案。

多个独立字块分成多个 item；同一段固定换行在 `text` 里用 `\n`（JSON 里的 `\n` 解析后就是真换行，别双重转义）。

**文字坐标也用全图**。招牌框是 `[100,100,500,300]`，牌上的字也要给它在画布上的实际位置，不是从招牌左上角重新算。

字数要有地方放：大标题十个字以内、小脚注、长段落是三回事，塞不下就加画布或拆图，别偷偷删用户的字。

### 常见错误

| 错误 | 正确做法 |
|---|---|
| 自创 `prompt` / `negative_prompt` / `seed` 根字段 | 只用 summary / items |
| 给 items 加 `children` | 全部平铺，坐标按全图 |
| `label="panel"` | 不是合法枚举；格背景用 `object`，类型放 `summary.canvas` |
| 草稿写 0.1–0.9 | 必须是真实像素 |
| xyxy 草稿直接标成 yxyx | 走转换公式 |
| 改了尺寸没改框 | 相对占比会变，重新规划或等比缩放 |
| 框越界 / `x0=x1` | 编译器不接受，修边界而不是绕过 |
| caption 说左、框在右 | 两者必须一致 |
| 只放 text 不写 caption | 缺必要字段与排版意图 |

## 光照写因果，材质写受光

不要写 `cinematic lighting, beautiful lighting`。写**光源在哪 → 照到哪个面 → 阴影留在哪 → 有没有反射补光**：

```
暖窗光从画面左侧照入，照亮近侧脸颊与鬓边橙发；远侧脸颊和颈部保留柔和冷影，
浅色桌面带来少量反射光。
```

材质靠受光方式区分，不是全都涂亮油：

| 材质 | 受光表现 |
|---|---|
| 棉布 | 宽缓的漫反射，明暗过渡平 |
| 绸缎 | 沿褶皱的长条高光 |
| 皮革 | 窄而亮的高光边 |
| 金属 | 集中的锐反光，不必自发光 |
| 玻璃 | 透射 + 边缘反光 |
| 湿石板 | 断裂的光带 |

同一束光下，这些材质必须有区别。羽毛、黑发、黑衣也不能糊成一个黑块。

## 改提示词的原则

每次改都返回**完整可用成稿**，不给"把第三句换成……"这种碎片。

只动受影响的部分：人物太大就改景别机位与主体占比；脸平就调主光作用面；多人串色就拆主语；共享物变多件就让所有描述指向同一件；字区挤就加画布或分块。

**不要用加质量形容词代替定位问题。**

## 出图前自查

人数与实例、身份与服装一致、属性归属谁、视线、支撑面、画面左右与角色自身左右、机位与取景是否容得下动作、光源与阴影方向、材质反应、可见文字原文与大小写、语言是否统一。

冲突只在**同一对象、同一部位、同一瞬间**成立：背对镜头越肩回望合理，一人坐一人站合理；镜头全脸大特写与完整全身同框、同一只手同时张开与握拳，则需要选一个状态。

Layout 额外查：字段与枚举、坐标越界、框面积为正、text 项完整、描述与框一致、最终是不是一行 `abs_centralized` + `yxyx` 整数框 JSON、有没有多余尺寸字段。合法 JSON 不等于模型一定照做，位置、数量、身份、文案要分别验。
